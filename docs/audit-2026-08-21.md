# System audit — 21 August 2026

Prompted by finding that the scene index had been built and then switched off
as a side effect of a merge, with nobody deciding it. The question this audit
asks is: **what else contradicts what this product is supposed to be?**

Checked against the rules in `CLAUDE.md`, both repositories, code as of the
memory-foundation work (CLIPIT#34).

Nothing here is fixed yet. Each item says what it costs and what fixing it
would involve, so the order of work is a decision rather than an assumption.

---

## 1. Anyone can resume someone else's session on a shared computer

**What happens:** the anonymous session token is kept in `localStorage`, which
survives closing the browser. Sessions last 30 days on the server. So on a
shared or public machine, the next person to open the app resumes the previous
person's session — their videos, their clips, their searches.

**Why it counts:** the recorded decision was that guest sessions are scoped to
the browser session (`sessionStorage`), and that an old guest session must
never be recoverable on a future visit. The code does the opposite, and there
is no `sessionStorage` anywhere in the frontend.

**Fix:** move the token to `sessionStorage`. One file. The cost is that closing
the tab loses access to your videos — which is what the decision intended, and
is the trade-off worth confirming before changing it.

## 2. Nothing is ever deleted

**What happens:** no cleanup job, no delete endpoint, no retention. Every
upload, proxy, chunk, clip and thumbnail stays in the bucket permanently —
including for sessions that expired 30 days ago and can never be accessed
again. A user cannot remove their own video.

**Why it counts:** two separate problems wearing one hat. Storage cost grows
forever and never falls. And people's video stays on our disks indefinitely
with no way for them to take it back.

**Fix:** a delete endpoint is small. A retention sweep is a scheduled job much
like the thumbnail backfill. What the retention window should be is a product
decision, not a technical one.

## 3. A moment the model found can be discarded and reported as absent

**What happens:** matches below `MIN_MATCH_CONFIDENCE` (0.3) are dropped. The
user is told nothing matched. The code comment at that line already states the
problem exactly — "a match the model DID report, thrown away by our own
threshold, reads downstream as 'the video does not contain that' — the one
failure the user cannot tell apart from a real absence" — and then logs it for
us instead of telling them.

**Why it counts:** it is the same failure as an unsearched chunk reported as
searched, which this codebase has now fixed three times in other places. The
difference is that here we know the moment exists and drop it anyway.

**Fix:** when a search returns nothing but discarded something, say so: "I saw
something at 04:12 I wasn't confident about." The mechanism already exists —
coverage gaps are reported this way.

## 4. The invented progress numbers are still in the API

**What happens:** `videoProgress` still returns 5%, 20%, 60%, 100% per stage.
The frontend stopped displaying them, but the API still publishes them.

**Why it counts:** the frontend fix hid the number rather than removing it. Any
other client — a future mobile app, an integration, a debugging session — reads
those as real.

**Fix:** either report real progress from ffmpeg, or drop `percent` from the
response and let `stage` speak. The second is honest and takes minutes.

## 5. Reading a long video at upload costs real money, silently

**What happens:** indexing now runs automatically on every upload, at roughly
$0.006 per two-minute chunk. The current maximum source length is six hours —
180 chunks, about **$1 per upload**, before anyone asks a single question.

**Why it counts:** it is a new, automatic, unbounded-by-length cost that nobody
sees until the bill. Not wrong — it is what makes questions cheap — but it
should be a decision.

**Fix:** options are a length cap on indexing, coarser chunks for long videos,
or leaving it and watching the numbers. Worth an explicit choice.

## 6. "High" and "Likely" are the model's opinion of itself

**What happens:** the confidence bar and its label come straight from the
number the model reports about its own answer. Nothing has ever compared that
number to whether the clip was actually right.

**Why it counts:** a 2-second clip rated "High" sitting above a 54-second clip
rated "Likely" is a real example from a real run. The label carries authority
it has not earned.

**Fix:** thumbs up/down data now exists (CLIPIT#33). Once there is enough of
it, the label can be derived from evidence — how long the thing is visible, how
directly it answers — instead of self-report.

## 7. Dead code that still has tests

- `extractFrames` and `planFrameTimestamps`: the old frame-sampling path from
  before the video model. Nothing calls `extractFrames` except its own test,
  which passes and means nothing.
- `'verification'` as a usage stage: nothing ever writes it.

**Why it counts:** a green test on unreachable code is worse than no test. It
reads as coverage.

**Fix:** delete both, and the tests with them.

## 8. Credentials for a provider we no longer use

`MINICPM_API_KEY`, `MINICPM_API_BASE_URL` and `MINICPM_MODEL` are still set on
the Railway worker service. No code references MiniCPM anywhere.

**Fix:** remove the variables. If the key is real, rotate it.

---

## What was checked and is fine

- **No credentials in the browser bundle.** The OpenRouter key is server-side
  only; the frontend carries nothing but the API URL.
- **Storage keys never leak** through the API. Every URL is signed and expires.
- **Model output is validated** before it reaches the database, in both the
  match parser and the new scene parser.
- **The user's instruction is passed through verbatim.** There are still no
  predetermined clip categories anywhere.
- **Failures are recorded rather than swallowed.** Every `catch` that discards
  an error says why it is safe to.
- **Ownership is checked** on every read and write of a clip request.

## Pattern worth naming

Six of the eight findings are the same mistake: **something asserted without
evidence.** A percentage nobody measured. A confidence nobody checked. A test
for code nobody calls. A moment discarded and reported as absent. It is the
same shape as the bug that started this audit, and as the two found during it
(a scene parser accepting wrong-shaped JSON as "nothing here", and a status
branch describing a failed upload as processing).

The rule in `CLAUDE.md` — never report an absence you did not verify — covers
the user-facing half. The other half is internal: **do not let code claim
something is true because it has no branch for it being false.**
